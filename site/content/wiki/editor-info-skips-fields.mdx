The [[level-editor|level editor]]'s Edit button asks for a level's info one field at a time: its name, author, music,
starting hearts, bombs and ropes, and next level. Every key press there counts twice, so each Enter moves two fields
on. The prompt only ever stops on the name, the music, the bombs and the next level: the author, the hearts and the
ropes keep what they had.

## What happens

The player clicks Edit, and the prompt asks for the LEVEL NAME. Enter, and it asks for the MUSIC, where AUTHOR
should have been. The player empties the music, and an Enter on the empty field does nothing; with LL typed, the
next Enter goes to START BOMBS, past START LIFE. The next goes to NEXT LEVEL, past START ROPE, and the last back to
editing <Cite clip="quirks/editor-info-skips-fields" />.

<Clip id="quirks/editor-info-skips-fields" />

## Why

GameMaker runs an object's "any key" event twice for each key press <Cite
quirk="5" row='The keyboard stages run the "no key" and "any key" events twice' />, and the editor's prompt
lives in that event. Each field moves the prompt on to the next when Enter is pressed and it isn't empty:

```gml objects/oLevelEditor/keypress_anykey.gml:201-211
else if (status == INFO_NAME)
{
    if (keyboard_key == vk_enter)
    {
        if (levelName != "")
        {
            status = INFO_AUTHOR;
            window_set_cursor(cr_default);
            oCursObj.visible = true;
        }
    }
```

The first run takes the prompt from the name to the author, and the second, now on the author, takes it on to the
music <Cite gml="objects/oLevelEditor/keypress_anykey.gml:218-228" />. The same happens from the music to the bombs
and from the bombs to the next level, so the fields after the name, the music and the bombs are never shown
<Cite quirk="1" />. They keep their values, ANONYMOUS, 4 and 4 in a new level
<Cite gml="objects/oLevelEditor/create.gml:20-26" />. Only an empty field stops a run: Enter on an emptied field
does nothing. The same doubling types the E that opens an exit's label or a sign's message into it, as the second
run is already editing the text <Cite gml="objects/oLevelEditor/keypress_anykey.gml:127-162" />.

## Reproducing it

Click Edit in the level editor and press Enter: the prompt goes from the name straight to the music. It happens to
anyone who sets a level's info. In the clip's replay the prompt opens on frame 356, and each Enter on a field that
isn't empty moves it two fields: to the music on 366, to the bombs on 386, to the next level on 398 and back to
editing on 414. The Enter on 378, on the emptied music, leaves it there. It's never on the author, the hearts or
the ropes <Cite replay="fidelity/replays/editor-build-test-save.txt" />. In another,
E over an exit labelled AB opens it as ABE <Cite replay="fidelity/replays/editor-doors-signs-new.txt" />.

## In the port

The spelunky.ai port reproduces it exactly: it's in docs/quirks.md's list of the 1.1 source's bugs
<Cite quirk="1" />, and the oracle's fingerprints of the two replays pin the prompt's fields. No option turns it off.
