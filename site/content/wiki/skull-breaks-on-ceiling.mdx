The [[skull|Skull]] moves by a copy of the [[jar|Jar]]'s code, with the speeds it breaks at lowered. One of
them was lowered past the point of meaning anything: a Skull thrown up breaks on any ceiling it reaches, at
any speed, where a Jar has to hit it hard.

## What happens

The player throws a Jar up at the ceiling. It arrives slowly and bounces off whole, only breaking when it
lands. Then he throws a Skull the same way: it arrives slower still, and shatters against the ceiling
<Cite clip="quirks/skull-breaks-on-ceiling" />.

<Clip id="quirks/skull-breaks-on-ceiling" />

## Why

The Skull's step is the Jar's, copied. Where it hits a ceiling going up, both test how fast it's going:

```gml objects/oSkull/step.gml:37-47
    if (colTop and yVel < 0)
    {
        if (yVel < 2) destroy = true;
        yVel = -yVel * 0.8;
    }
    
    if (colLeft or colRight)
    {
        if (abs(xVel) > 2) destroy = true;
        xVel = -xVel * 0.5;
    }
```

`yVel < 0` is moving up, and inside that test `yVel < 2` always holds, so the Skull breaks on every ceiling.
The Jar's line is `if (yVel < -3)`: rising faster than 3 pixels a step, as the step has already added its
gravity, faster than 3.6 before it <Cite gml="objects/oJar/step.gml:37-41" />. Against a wall the Skull's
threshold is lower as well, 2 pixels a step across where the Jar's is 3, but that one still means something
<Cite gml="objects/oJar/step.gml:43-47" /> <Cite quirk="1" />.

## Reproducing it

Throw a Skull straight up under a ceiling it can reach: it breaks there, however slowly it arrives. The
replay of the clip's staged scene, on a custom level, throws a Jar up under a ceiling four blocks up; it
reaches it rising at 3 pixels a step and bounces off, breaking only when it lands. A Skull thrown the same way
reaches it at 2.4 and breaks there <Cite replay="fidelity/replays/item-skull-breaks-on-ceiling.txt" />. The
wall's lower threshold is read in the code, and not yet checked against the original game.

## In the port

The spelunky.ai port reproduces it exactly: it's in docs/quirks.md's list of the 1.1 source's bugs
<Cite quirk="1" />, and the oracle's fingerprint of the replay pins both throws. No option turns it off.
